# Risks, gates and open questions (2026-11-03)

## Gates touched

| Gate | How |
|---|---|
| G-NOVELTY | Claims are limited to what `PRIOR-ART.md` (2026-11-03) supports. Do not say "first storage schema" or "first typed storage" |
| G-OUTREACH | `drafts/sdk-1818-comment.md` and `drafts/SEP-storage-schema.md` are not posted. The user posts them |
| G-LICENCE | Demo copies: soroban-examples token/increment (Apache-2.0) and OZ fungible-pausable example (MIT), unmodified apart from the token/increment annotations. Attribution rows are proposed in `TASKS.md` (Cross-project requests) for root `NOTICE` and `docs/THIRD_PARTY.md`, because this agent may not edit root files. The SAC sidecar describes soroban-env-host (Apache-2.0) types and copies no code |
| G-VALUE / G-SECRETS | Network use is read-only mainnet RPC only (CLI, capture script, and the site's live mode in the visitor's browser). No keys and no transactions |

## Risks

| ID | Risk | Likelihood / impact | Mitigation / status |
|---|---|---|---|
| R-01 | SDF ships its own storage-schema emission under #1762 with a different format | medium / high | written to plug into #1762: same attribute shape; the section format is independent of how it is emitted. Adoption of any compatible design counts as a win (user strategy) |
| R-02 | PR #2127 lands with its own conventions | low-medium / medium | its keys map to `TAGGED` with named fields. Its value encoding is unverified (R-08) |
| R-03 | A SEP that *mandates* layouts would be declined (Leigh on discussion #1991, 2026-08-03 [S: discovery note]) | n/a | the format is informational and opt-in; this is stated in SPEC 1 and in the SEP |
| R-04 | Opposition on principle (mootz12: internal types do not belong in external ABIs) | high / medium | separate section, not the spec; sidecar option has zero on-chain cost; size measured [M] |
| R-05 | stellar-cli's spec-shaking or optimise pass may drop unknown custom sections | was unknown / high | **checked for CLI 25.2.0 (2026-11-03): kept** by `stellar contract build` (which does shaking v2; soroban-sdk 28 refuses to build without it) and by `--optimize`. Newer CLIs are unchecked (SSC-012). Fallback: inject after building |
| R-06 | `link_section` statics from **dependency** crates may not reach the final module | **checked 2026-11-08** / medium | they do, if the contract crate references the library; without a reference the library is not linked and its declarations are silently absent (measured: 5 key entries vs 1, build succeeds). Documented in SPEC 8.2 and the site; detection ticket SSC-030 |
| R-12 | Macro statics marked `#[used]` were also copied into the wasm data segment (rustc 1.97.1), doubling the cost | happened / medium | fixed: `#[used]` removed; the size test (`size_cost_is_section_bytes_only`) asserts identical code and delta = section bytes |
| R-13 | Dependency advisories (checked 2026-11-08, local RustSec db of 1,422 advisories, `cargo audit --no-yanked --no-fetch`) | low | main workspace `Cargo.lock` (CLI, core, browser engine): no advisory. `demos/Cargo.lock` (test-only soroban-sdk testutils tree, never shipped): RUSTSEC-2026-0387 `crypto-bigint 0.5.5` (timing variability; reached through soroban-sdk) and `paste` unmaintained (warning). Not in the CLI or engine. Not checked: yanked crates and `pnpm audit` (network unreachable); SSC-033 |
| R-14 | Reviewer concern: demo token `transfer`/`approve` lack `require_auth` | checked 2026-11-08 / none for `oz-extern` | `Base::transfer` and `Base::approve` in OZ stellar-tokens 0.8.0 call `from.require_auth()` / `owner.require_auth()` themselves (`src/fungible/storage.rs` lines 195 and 336); adding the call in the wrapper fails with `Auth, ExistingValue` ("frame is already authorized"), tried and reverted. `oz-pausable` is the upstream OZ example, kept unmodified. The demo contracts stay DEMO-ONLY and are never deployed |
| R-07 | `<T>::spec_xdr()` is an undocumented SDK API (`pub const fn` generated by `#[contracttype]`) | medium / medium | present in sdk 25.3.2 and 28.0.0 [P]; `embed_types = false` opt-out; a sidecar remains available |
| R-08 | Value encoding of #2127's `#[contractdata]` body (non-key fields) not read | — | open question; read `derive_contract_data.rs` before claiming compatibility beyond keys |
| R-09 | Schema describes current code only; entries written before an upgrade show `value_mismatch` | certain / low | reported honestly; history-aware selection is SSC-020 |
| R-10 | Process incident (2026-11-03): running `cargo search` inside the cloned OZ checkout picked up its `rust-toolchain.toml` (`channel = "stable"`) and started a rustup update of the user's default `stable` toolchain; the session dropped mid-update and left `stable` without `rustc` | happened | repaired with `rustup update stable` (now 1.99.1). The kit's pinned 1.97.1 toolchain was not touched. Rule added to AGENTS.md (no cargo in upstream checkouts). rustup's self-update to 1.29.3 failed on a connection reset; rustup stays 1.29.0 |
| R-11 | RPC cannot enumerate a contract's keys, so decoding needs known keys or an index | certain / medium | instance map, key builder from schema + args, getEvents-derived addresses; a ledger-data index (`holders-at-ledger`/Galexie) is the long-term source |

| R-13 | The browser engine is 1.1 MB (syn and the full stellar-xdr type set are linked) | certain / low | loads once per visit; the page says so while loading; SSC-031 to shrink |
| R-14 | Live mode depends on a public RPC (`mainnet.sorobanrpc.com`) and its CORS policy | medium / low | read-only; errors are shown, nothing is decoded on failure; scenarios work offline; DEPLOY.md lists a fallback RPC as optional |
