## Method

{size.method}.

- `*.raw.wasm` and `*.noschema.wasm` come from the identical `cargo rustc` command; the baseline adds `--cfg sik_storage_schema_off`, which removes every static the macros emit and nothing else.
- `code_identical` compares a digest of every non-custom section. `identical_after_strip` removes the `contractstoragev0` sections and compares the whole file.
- "Share of this wasm" divides the section bytes by the size of the file that carries the section. It is not the increase over a contract without one: for that, use the baseline column. The token's increase is {token.baseline.delta_bytes} bytes on {fmt(token.baseline.wasm_bytes)} bytes, {(100 * token.baseline.delta_bytes / token.baseline.wasm_bytes).toFixed(2)}% (raw pair), while the shaken, optimised token carries the same section in {fmt(rows.find((r) => r.wasm === 'ssc_demo_token.wasm').wasm_bytes)} bytes, a {rows.find((r) => r.wasm === 'ssc_demo_token.wasm').share_of_wasm_percent}% share.
- The share of this wasm is large for the shaken (`stellar contract build`) outputs because those are small: the token is {fmt(rows.find((r) => r.wasm === 'ssc_demo_token.wasm').wasm_bytes)} bytes after spec shaking and size optimisation. The section's absolute size depends on the number of keys and types and on their doc strings, not on the contract's code.
- Cost on chain: wasm upload fees scale with code size. A contract that does not want the bytes on chain can keep the same schema as a sidecar file at zero on-chain cost.

## A bug the measurement found

The first macro version marked its statics `#[used]`. With rustc 1.97.1 that also copied the bytes into the wasm data segment, so the cost doubled and the code changed. `#[used]` was removed; the section is still emitted, and the CLI test `size_cost_is_section_bytes_only` now asserts identical code and a delta equal to the section bytes.
